Router:
-------
"The Router in Laravel is a core system that maps incoming HTTP requests to specific code execution points (like Controllers or Closures).

We primarily manage them in two places: web.php for web browser traffic (which handles sessions and outputs HTML templates), and api.php for stateless API traffic (which handles token authentication and outputs raw data like JSON)."

Route::get("/", [TaskController, "index"]);

Route::get("/about", () => {
    return "/about";
})

“Why api.php is stateless?”

Answer:

Because APIs usually do not maintain sessions between requests. Each request contains its own authentication information, commonly through tokens.

controller:
---------
controller is a coordinator which help to handle the request and response lifecycle. while it can handle validation, the main job of controller is handle the validated data and interact with the business, model logics and return a response

“Why shouldn’t we put all logic inside controller?”

Answer:

Because controllers should remain lightweight and focused on request handling. Complex business logic is usually moved to services, repositories, or model layers for better maintainability and scalability.

public function store(StoreTaskRequest $request) {
    $validated = $request->validated();

    $task = $Task::create($validated);

    return response()->json([
        'success' => true,
        'data' => $task
    ], 201);
}


Model:
-------
A model in Laravel represents a database table and acts as the application's data layer using Eloquent ORM.

It is responsible for interacting with the database, handling CRUD operations, defining relationships between tables, and managing business-related data logic.

Models help developers work with database records using object-oriented syntax instead of writing raw SQL queries.

example: find()
findOrFail()
where()
delete()
latest()
paginate()

Middleware acts as a filtering layer between the incoming HTTP request and the application controllers.

It is used to inspect, validate, or block requests before they reach the controller.

Common use cases include:

authentication
authorization
logging
rate limiting
CORS handling

Middleware helps secure and control application flow.

“Can middleware run after response too?”

Answer:

Yes. Middleware can process both before and after the request lifecycle using the $next($request) flow.

Example:

public function handle($request, closure $next) {
    // before 
    $response = $next($request);

    // after 
    return $response;
}

Route::middleware("auth")->group(() => {
    Route::get("dashboard", function () {
        return view('dashboard');
    })
})

Dependency Injection:
--------------------
Dependency Injection is a design pattern where a class receives its dependencies from outside instead of creating them internally.

This improves:

loose coupling
testability
maintainability

In Laravel, Dependency Injection is managed automatically by the Service Container, which resolves and injects required class dependencies.

useState:
--------
     useState is a React Hook used to manage state inside funcational component.
     It allows components store and update dynamic data without refreshing page.
     when the state updates, the component renders automatically.

     const [ count, setCount ] = useState();

     No. state updates are asynchronous in React.
