what is Eloquent Model?
+++++++++++++++++++++++++

Gemini said
In Laravel, Eloquent is an Object-Relational Mapper (ORM) that makes interacting with your database feel like you are just playing with standard PHP objects.

Instead of writing complex SQL queries like SELECT * FROM users WHERE active = 1;, you can simply write User::where('active', 1)->get();.

1. How It Works (The Mapping)
Eloquent follows the Active Record pattern. This means:

A Database Table maps to a PHP Class (the Model).

A Table Column maps to a Class Property.

A Table Row maps to an Object Instance.


example:
----------

Task	         Raw SQL / Query Builder	                        Eloquent ORM
----             -----------------------                            ------------
Fetch All	     DB::table('users')->get();	                        User::all();
Find by ID	     DB::table('users')->where('id', 1)->first();	    User::find(1);
Insert	         DB::table('users')->insert(['name' => 'Joe']);	    $user = new User; $user->name = 'Joe'; $user->save();

        You are exactly right! These are known as Magic Methods in PHP. While they are built into PHP itself, Laravel’s Eloquent uses them heavily to do its "magic."Magic methods always start with a double underscore __ and are triggered automatically when you interact with an object in a way it wasn't expecting.1. __get($property) and __set($property, $value)These are triggered when you try to access or write to a property that is not defined or is private in the class.__get(): Runs when you try to read $object->variable.__set(): Runs when you try to write $object->variable = 'value'.Why Laravel needs them:In an Eloquent Model, you don't actually define properties like public $name; or public $email;. Instead, Eloquent uses __get and __set to dynamically fetch those values from the database "attributes" array.PHP// Inside a Laravel Model
$user = User::find(1);

// This triggers __get('name') because 'name' isn't a real property in the User class.
// Laravel looks inside its internal $attributes array and returns the value.
echo $user->name; 
2. __call($method, $arguments)This is triggered when you try to call a method that does not exist inside the class.Why Laravel needs them:This is how Laravel provides such a clean syntax for things like the Query Builder. When you call User::where(...), the User model doesn't actually have a where method!Instead:__call is triggered.Laravel realizes you want to run a database query.It "passes the ball" to the Query Builder class to handle the work.PHP$user = new User();
$user->someNonExistentMethod(); // Triggers __call('someNonExistentMethod', [])
